// THE ROOT CAUSE

SQL injection happens when user-supplied input gets concatenated directly into a SQL query string instead of being treated as pure data. The database has no way to tell where the developer's intended command ends and the attacker's payload begins — to the database, it's all just one query.

# Python — string concatenation username = request.form["username"] query = f"SELECT * FROM users WHERE username = '{username}'" db.execute(query) # Java — same flaw String query = "SELECT * FROM users WHERE id = " + userId; stmt.executeQuery(query);
# Python — the database driver handles escaping query = "SELECT * FROM users WHERE username = ?" db.execute(query, (username,)) # Java — PreparedStatement PreparedStatement stmt = conn.prepareStatement( "SELECT * FROM users WHERE id = ?"); stmt.setInt(1, userId);
WHY THIS WORKS

In the vulnerable version, the query structure and the user's data are the exact same string by the time the database sees it. In the safe version, the placeholder ? is sent to the database separately from the value — the database knows definitively "this entire value is data, never treat any part of it as command syntax," no matter what characters it contains.

WHAT JUST HAPPENED

Every payload you just tried follows the same root principle: a quote character (') closes the string literal early, and everything after it becomes part of the SQL command itself rather than part of the data. OR '1'='1' adds a condition that's always true. -- comments out the rest of the original query so a trailing quote or parenthesis doesn't cause a syntax error.

// SQLMAP — THE INDUSTRY TOOL

Manual testing teaches you the mental model. In real assessments, sqlmap automates discovery and exploitation once you suspect a parameter is vulnerable.

# Basic test against a suspected parameter sqlmap -u "http://target.com/page.php?id=1" --batch # If vulnerable, enumerate database names sqlmap -u "http://target.com/page.php?id=1" --dbs --batch # Dump a specific table sqlmap -u "http://target.com/page.php?id=1" -D mydb -T users --dump --batch # Testing a POST request instead of GET sqlmap -u "http://target.com/login" --data "user=admin&pass=test" --batch
LEGAL BOUNDARY

sqlmap and every technique on this page are for systems you own or have explicit written authorization to test — PortSwigger labs, TryHackMe, HackTheBox, your own local Juice Shop instance. Running this against anything else is a computer crime in essentially every jurisdiction, regardless of intent.
