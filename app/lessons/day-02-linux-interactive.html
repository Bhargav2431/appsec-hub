OPERATION 01

Navigate the Filesystem

Before you can attack a system, you must move through it blindfolded.

Linux has no "My Computer" or Finder window. You navigate through text commands. The filesystem is a tree. You are always somewhere in that tree. These commands tell you where you are and let you move.

$ pwd
Print Working Directory. Shows your current location.
The "I'm lost, where am I?" command. First thing to type in an unfamiliar shell.
$ ls
List files in current folder.
Windows equivalent: just looking at a folder. Do this constantly.
$ ls -la
List ALL files including hidden ones, with details.
The X-Ray vision version. Hidden files start with a dot (.bashrc, .ssh, .env). Security engineers always use -la — secrets hide in hidden files.
SECURITY
$ cd folder/
Change directory. Move into a folder.
Type cd then Tab to autocomplete filenames. Saves enormous time.
$ cd ..
Go up one level (to parent folder).
Two dots = parent. One dot = current. Weird but universal.
$ cd ~
Go to home directory.
Tilde (~) = home. Always your safe starting point. Like pressing "Home" on Windows.

The Submarine Analogy. Your terminal is a submarine. You can't see outside. pwd = depth gauge (where are you?). ls = sonar (what's around you?). cd = propeller (move forward). cd .. = reverse. Without these three reflexes, you're blind underwater.

# Boot Kali VM. Open terminal. Run these in order:
$ pwd
/home/kali
$ ls -la
$ cd /etc
$ ls -la
# /etc holds system config files — a goldmine for security
$ cd ~
# Back to safety

When you hack a machine (or do a pentest), ls -la is the first command you run after getting access. Hidden files in home directories often contain SSH keys, passwords, tokens. A .bash_history file shows every command the user ran. These are your first clues.

OPERATION 02

Manipulate Files

Create, destroy, copy, rename. These are your hands in the Linux world.

$ touch file.txt
Create an empty file. Also updates timestamps.
Like tapping something to create it. Think of touching a blank piece of paper.
$ mkdir myfolder
Make directory (folder).
mkdir -p makes nested folders at once: mkdir -p a/b/c
$ cat file.txt
Print file contents to screen.
Short files: cat. Long files: less (page by page, q to quit).
USE DAILY
$ cp file.txt copy.txt
Copy a file. cp -r folder/ dest/ copies folders.
Always copies — original stays. cp source destination.
$ mv file.txt new.txt
Move OR rename a file. Same command for both.
mv within same folder = rename. mv to different path = move.
$ rm file.txt
Delete a file. Permanently. No recycle bin.
The point of no return. rm -r deletes folders. NEVER run rm -rf / on a real system.
PERMANENT
$ tail -f log.txt
Watch a file grow in real time. Ctrl+C to stop.
Security gold: tail -f /var/log/auth.log shows live login attempts on a server.
SECURITY
$ head -20 / tail -20
Show first or last 20 lines of a file.
Log files are huge. head and tail show the interesting bits without loading everything.

rm is permanent on Linux. There is no "undo." The trash can doesn't exist. Double-check before running it. Never run rm -rf / — that deletes the entire operating system. People have lost entire servers this way.

OPERATION 03

Find What's Hidden

These commands are your metal detector. They find needles in haystacks.

$ grep "password" file.txt
Search for a string inside a file. Prints matching lines.
grep = Global Regular Expression Print. Think of it as Ctrl+F for the terminal.
USE DAILY
$ grep -r "TODO" /home/
Recursive search — searches ALL files inside a folder and its subfolders.
The -r flag is the secret weapon. grep -r "api_key" /var/www/ is a classic recon move.
SECURITY
$ grep -i "error" log.txt
Case-insensitive search. Matches "Error", "ERROR", "error".
Always use -i when searching logs — servers aren't consistent with capitalization.
$ find / -name "*.conf"
Find files by name pattern across the whole filesystem.
Add 2>/dev/null to silence permission errors: find / -name "*.conf" 2>/dev/null
SECURITY
# Security reconnaissance: find potential secrets in a folder
$ grep -rE "(password|api_key|secret|token|AWS)" /etc/ 2>/dev/null

# Find world-readable sensitive files
$ find /etc -name "*.conf" -readable 2>/dev/null

# Search a log for failed login attempts
$ grep -i "failed" /var/log/auth.log 2>/dev/null | head -20

These three commands are how security engineers find hardcoded credentials in source code. On Day 20 (DevSecOps), you'll integrate automated grep-style scanning (called secret scanning) into GitHub CI/CD pipelines using tools like TruffleHog and GitLeaks — which are just sophisticated versions of grep -rE.

OPERATION 04

Control Access

Permission misconfigurations cause more security incidents than almost anything else. Understand this deeply.

Every file in Linux has permissions. Three groups of people can interact with it: the Owner (u), the Group (g), and Everyone else (o). Each group can have three permissions: Read (r=4), Write (w=2), Execute (x=1).

When you run ls -la, you see something like -rwxr-xr--. This is three groups of three bits telling you exactly who can do what.

chmod 000 file Nobody can do anything

Common values to memorize:
chmod 755 = owner does anything (7), others read+execute (5). Standard for programs.
chmod 644 = owner read+write (6), others read-only (4). Standard for files.
chmod 600 = owner read+write, nobody else. Use for SSH keys and secrets.
chmod 777 = everyone can do everything. DANGEROUS. Never in production.

$ chmod +x script.sh
Make a file executable. Required before running scripts.
+x adds execute. You'll do this every time you write a bash script.
USE DAILY
$ sudo command
Run a command as administrator (superuser).
"sudo" = "superuser do." Getting sudo access is the #1 goal of privilege escalation attacks.
SECURITY
$ whoami
Print current logged-in username.
First command after gaining shell access in a pentest. Am I root yet?
SECURITY

On Day 39 (Penetration Testing AWS), privilege escalation is a key attack. On Linux systems, it means going from a regular user to root (sudo). Understanding permissions now means you'll understand how attackers exploit misconfigurations — like chmod 777 files that shouldn't be writable, or SUID bits that let normal users run as root.

OPERATION 05

Build Command Chains

Single commands are tools. Pipes turn them into machines.

The real power of Linux is chaining commands together. The output of one command becomes the input of the next. You build data processing pipelines from simple building blocks.

$ ls | grep "txt"
Pipe ls output into grep to filter only .txt files.
The pipe | is like a worker passing their result to the next worker in line.
USE DAILY
$ cat file.txt | wc -l
Count the number of lines in a file.
wc = word count. -l = lines. -w = words. -c = characters.
$ ls > output.txt
Save output to a file. Overwrites if exists.
> is a "funnel." Instead of screen, output goes to file. OVERWRITES.
$ ls >> output.txt
Append output to a file. Adds to end without erasing.
>> = keep adding. Good for logs. > = overwrite. >> = append. Don't confuse them.
$ 2>/dev/null
Throw error messages in the trash (they still clutter output).
/dev/null is Linux's black hole. Anything sent there disappears. You'll see this everywhere.
$ sort | uniq -c
Sort lines then count unique values.
Classic log analysis combo: who made the most requests? sort | uniq -c | sort -rn
# Real security pipeline: find failed logins, count by IP
$ grep "Failed" /var/log/auth.log 2>/dev/null | \
  awk '{print $11}' | sort | uniq -c | sort -rn | head -10

# Count how many files are in the current directory
$ ls | wc -l

# Save nmap results to a file
$ nmap -sV 192.168.1.1 > scan_results.txt 2>&1

The Assembly Line. Imagine a factory making a product. Each worker does one job and passes the result to the next. That's a pipe. cat log.txt | grep "error" | sort | uniq -c is a 4-worker assembly line: read file → filter errors → sort them → count unique ones. Each command is simple. The chain is powerful.

OPERATION 07 — BUILD SOMETHING

Your First Security Script

Combining everything you've learned into one working tool.

A bash script is just a text file with commands in it. Instead of typing 10 commands manually every time, you put them in a file and run them with one command.

# Step 1: Create the scripts folder
$ mkdir -p ~/scripts
$ cd ~/scripts

# Step 2: Create the script file
$ cat > find_secrets.sh << 'EOF'
#!/bin/bash
# Day 2 Security Script: Find potential secrets in files

echo "=== Secret Scanner ==="
echo "Target: $1"
echo ""

TARGET=${1:-"$HOME"}

echo "[*] Searching for credentials..."
grep -rE "(password|passwd|api_key|secret|token|AWS)" \
  $TARGET 2>/dev/null | head -20

echo ""
echo "[*] Searching for .env files..."
find $TARGET -name ".env" 2>/dev/null

echo ""
echo "[*] World-writable files (security risk)..."
find $TARGET -perm -o+w -type f 2>/dev/null | head -10

echo ""
echo "=== Scan Complete ==="
EOF

# Step 3: Make it executable
$ chmod +x find_secrets.sh

# Step 4: Run it on your home directory
$ ./find_secrets.sh ~

# Step 5: Run it on /etc to see system configs
$ ./find_secrets.sh /etc

This is a primitive version of what Semgrep and TruffleHog do commercially — search code for hardcoded secrets. On Day 20 (DevSecOps), you'll automate exactly this kind of scan in a GitHub pipeline. Today you built the manual version from scratch. That's the right order to learn it.
