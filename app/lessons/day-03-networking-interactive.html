INTERCEPT 01 // IP ADDRESSES

Every Device Has an Address

Understand IPs before you can attack or defend anything on a network.

An IP address is a number assigned to every device on a network. Without it, data has no destination. Like a postal address for computers.

There are two versions in use today: IPv4 (the classic, 4 numbers like 192.168.1.5) and IPv6 (the newer, longer one like 2001:db8::1 — we ran out of IPv4 addresses).

Private IPs (used inside homes/offices — internet can't reach them directly):
10.0.0.0 – 10.255.255.255  |  172.16.0.0 – 172.31.255.255  |  192.168.0.0 – 192.168.255.255

Public IPs — unique on the internet. Your home gets one from your ISP.
Loopback — 127.0.0.1 ("localhost") — your own machine talking to itself.

The Street Address Analogy. Private IP = apartment number inside a building (only people in the building know it). Public IP = the building's street address (the whole world can find it). NAT (Network Address Translation) is the building receptionist — they receive mail addressed to the building and forward it to the right apartment.

INTERCEPT 02 // TCP vs UDP

Two Ways to Send Data

Not all network traffic is equal. Know which protocol and why.

Once you have an IP address (destination) and a port (which service), you need a transport protocol. Two options, very different tradeoffs.

ASPECTTCPUDP
ReliabilityGuaranteed delivery. Retries if lost.No guarantee. Packets can drop.
SpeedSlower (handshake + confirmation)Faster (fire and forget)
OrderPackets arrive in orderPackets can arrive out of order
ConnectionRequires handshake first (SYN→SYN-ACK→ACK)No connection needed
Used forHTTP, HTTPS, SSH, FTP, databasesDNS, video streaming, gaming, VoIP
AppSec relevanceSYN flood attacks target TCP handshakeUDP flood for DDoS, DNS amplification

The Phone Call vs Shouting.
TCP = a phone call. You dial, they answer, you confirm they can hear you, then talk. If they miss something, you repeat it.
UDP = shouting information into a crowd. Fast, no confirmation. Some people hear it, some don't. Fine for live sports scores; bad for banking.

TCP SYN Flood: An attacker sends thousands of SYN packets (step 1 of handshake) but never completes the handshake. Server reserves memory for each half-open connection until it runs out of resources. This is a classic DoS attack. Countermeasure: SYN cookies, rate limiting.

INTERCEPT 03 // PORTS

The Port Directory

IP gets you to the building. The port tells you which door to knock on.

A server runs many services at once — a web server, SSH, a database. Each gets a port number (0–65535). When data arrives, the port number tells the OS which program should handle it. Search or filter below.

Port scanning (nmap) is how attackers discover which services are running on a target. Open port 3306 on the internet? That's MySQL exposed — attacker tries default credentials. Open 3389? That's RDP — target for brute force. Your job on Day 22 is to do recon exactly like this. Understanding ports now means you understand what every scan result means.

INTERCEPT 04 // DNS

How Domains Become IPs

The internet's phonebook. Understand it to attack it or defend it.

You type google.com. Your computer doesn't know what that is — it only understands IP addresses. DNS (Domain Name System) translates the name to an IP. Click each step to trace the journey.

DNS record types you need to know:
A — domain → IPv4 address (most common)
AAAA — domain → IPv6 address
CNAME — alias pointing to another domain
MX — mail server for the domain (email attacks start here)
TXT — text records (SPF, DKIM, DMARC — email security)
NS — nameservers for the domain

# Basic DNS lookup $ dig google.com # Get only the answer section $ dig google.com +short # Get mail servers $ dig google.com MX # Get text records (shows SPF/security info) $ dig google.com TXT # Query a specific DNS server $ dig @8.8.8.8 google.com # Reverse lookup (IP to domain) $ dig -x 8.8.8.8 # Enumerate subdomains (recon technique) $ dig www.google.com +short $ dig mail.google.com +short

DNS attacks you'll encounter:
DNS spoofing/poisoning — attacker injects fake records so google.com points to their server.
DNS enumeration — discovering all subdomains of a target (Day 22 recon).
DNS over HTTPS (DoH) — encrypts DNS queries so ISPs can't see where you browse.
DNS amplification DDoS — use DNS servers to flood a target with traffic.

INTERCEPT 05 // TLS/SSL

How HTTPS Encryption Works

The padlock icon. What's actually happening underneath it.

TLS (Transport Layer Security, incorrectly still called SSL) wraps HTTP in an encrypted tunnel. Without it, everything you type (passwords, credit card numbers) is readable by anyone on the same network — a coffee shop attacker, your ISP, a compromised router.

The TLS Handshake (simplified):
1. Client says "Hello" and lists encryption algorithms it supports
2. Server sends its certificate (proves it's really google.com, not an impersonator)
3. Certificate is verified against a trusted Certificate Authority (CA)
4. Both sides agree on encryption keys without sending them over the wire
5. Encrypted tunnel open — all data now encrypted

The Sealed + Certified Envelope. Without TLS = sending a postcard (everyone reads it). With TLS = sealed envelope with tamper-evident seal. But critically, TLS also verifies the address on the envelope — a certificate proves you're talking to the real server, not an impersonator pretending to be your bank.

# See a site's TLS certificate $ echo | openssl s_client -connect google.com:443 2>/dev/null | openssl x509 -noout -dates # Simpler: check with curl $ curl -v https://google.com 2>&1 | grep -E "SSL|certificate|expire" # Check what cipher suite is being used $ nmap --script ssl-cert -p 443 google.com

TLS vulnerabilities: Expired certificates (browser warning = still visited by users), self-signed certificates (no verification = easy MITM), weak cipher suites (attackers can downgrade encryption), certificate pinning bypass (used in mobile app pentesting).
