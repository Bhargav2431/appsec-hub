// THE INTERCEPTION CHAIN

Burp Suite is an intercepting proxy. It sits physically between your browser and the target server, and every byte that flows in either direction passes through it first.

Nothing reaches the target without passing through Burp first, and nothing comes back without passing through it again. This is what makes inspection and modification possible — you're not asking the browser nicely to show you its traffic, you're sitting in the middle of the wire.

Intruder automates what Repeater does manually. You mark a position in the request with §position§ markers, load a wordlist, and Burp fires the request once per entry in the list.

Community Edition rate-limits this intentionally — it's still functional for small wordlists, just not built for speed. Four attack types: Sniper (one payload set, cycles through one position at a time), Battering Ram (same payload in every position simultaneously), Pitchfork (one payload list per position, in lockstep), Cluster Bomb (every combination of every list).
Comparer diffs two requests or responses side-by-side, byte for byte. The single best use case: sending a login attempt with a valid username next to one with an invalid username, and finding the exact bytes that differ — which is how you confirm a username enumeration vulnerability exists before you've even tried a single password.
// THE REST OF THE TABS, FOR REFERENCE
Repeater
Manually modify and resend one request, repeatedly. This is where the actual hands-on testing happens — you'll spend more time here than every other tab combined.
MOST USED
Proxy / HTTP History
The running log of everything that's passed through Burp. Your evidence trail, and the place you'll right-click to send something interesting to Repeater.
Target / Site Map
An auto-built map of every host and path discovered so far. Useful for defining scope before you start testing in earnest.
Intruder
Automated payload-list attacks. Brute force, fuzzing, credential stuffing — anything that means "try this list of values in this position, many times."
Decoder
Base64, URL encoding, hex, HTML entities. Essential the moment you find a JWT, a session token, or any value that looks like encoded noise.
Comparer
Byte-level diff between two requests or responses. The fastest way to spot exactly what changed between two near-identical server replies.
▸ THE ACTUAL WORKFLOW

Browse the target normally with the proxy running. Find something interesting in the HTTP History list. Right-click → Send to Repeater. Modify a parameter, a header, the body — whatever your hypothesis is. Send. Read the response. Adjust the hypothesis. Repeat. This loop, run dozens of times against dozens of endpoints, is most of what an AppSec engineer's actual working day looks like.
